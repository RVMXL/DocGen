# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 0.6.x  | ✅ актуальная |
| < 0.6  | ❌ не поддерживается |

## Как сообщить об уязвимости

Используйте **приватные сообщения о безопасности GitHub** (Security → Advisories → «Report a vulnerability») в этом репозитории — это конфиденциальный канал. Публичные issue для сообщений об уязвимостях не используйте.

Ответ — в течение 14 дней; после выпуска исправления публикуется релиз и advisories.

## Модель безопасности DocGen

### Архитектура без сервера

Начиная с 0.2.0 (текущая архитектура — 0.6.x) DocGen — **статическое клиентское приложение** (web/Android/десктоп):

- Каталог шаблонов — статические данные, встроенные в приложение.
- Генерация .docx/.pdf выполняется на устройстве пользователя (docx, pdf-lib).
- Серверная часть, API, база данных и аутентификация отсутствуют по дизайну.
- Приложение не отправляет пользовательские данные никуда; единственные исходящие переходы — официальные госпорталы по ссылкам на карточках (по явному клику пользователя).

### Поверхность атаки

- **Скомпрометированные зависимости**: сборка CI воспроизводима (`bun.lock`), все `actions/` в workflow запины по SHA-256, публикация релиза — только из CI репозитория.
- **Подпись Android**: APK подписывается upload-ключом, который существует только в GitHub Secrets (base64) и в локальной резервной копии владельца. В workflow зашит SHA-256 пин ключа и сертификата — подмена секрета или ключа останавливает сборку. Ключ в git не попадает (см. `.gitignore`).
- **Десктоп (Electron)**: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, внешние ссылки открываются в системном браузере. Приложение не подписано коммерческим сертификатом (SmartScreen/Gatekeeper предупреждают) — сверяйте SHA-256 файлов из `SHA256SUMS.txt` релиза.
- **Web-развёртывание**: статика; рекомендуется HTTPS-хостинг и заголовки CSP на усмотрение администратора, например:
  `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`
  (inline-стили нужны печатным стилям Next.js).

### Известные ограничения

- Данные, введённые в формы, хранятся только в памяти страницы и localStorage (язык/страна онбординга); на общих компьютерах это остаётся локально, но не защищено от локального доступа к профилю браузера.
- Печатные формы не являются юридической консультацией; актуальность реквизитов и норм проверяйте по официальным источникам стран.
