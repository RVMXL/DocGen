# Политика безопасности

## Поддерживаемые версии

Обновления безопасности получает только актуальная линейка версий:

| Версия | Поддержка |
| ------ | --------- |
| последняя из [Releases](https://github.com/RVMXL/DocGen/releases) | ✅ |
| предыдущие | ❌ |

Рекомендуется всегда использовать последнюю версию. Android-релизы подписываются одним стабильным ключом, поэтому обновление ставится поверх старой установки без удаления данных; SHA-256 сертификата подписи опубликован в README и сверяется CI в каждом релизе.

## Как сообщить об уязвимости

Пожалуйста, **не публикуйте** подробности уязвимости в Issues.

Используйте приватные отчёты GitHub: вкладка **Security** → **Report a vulnerability** этого репозитория. Отчёт видит только владелец репозитория.

В отчёте укажите:

- версию (тег релиза или коммит) и платформу (сервер / Windows / Linux / macOS / Android);
- как развёрнут DocGen (локально, в локальной сети, на VPS; за каким reverse-proxy, если есть);
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- оценку серьёзности, если она вам известна.

Ответ — в течение **7 дней**. После подтверждения исправление попадает в следующий релиз; об обнаружившей уязвимость стороне можно упомянуть в заметках релиза (по желанию).

## Поверхность атаки (коротко)

- **Генерация документов — локальный процесс**: шаблоны, подстановки значений и рендер .docx/.pdf выполняются на самом сервере DocGen; наружу не уходят ни данные форм, ни файлы.
- **БД SQLite без сети**: каталог хранится в локальном файле; при публичном развёртывании закрывайте порт сервера reverse-proxy с HTTPS и не выставляйте файл БД наружу.
- **Доступ к `/api/generate` не требует аутентификации** — это осознанное решение для локального/семейного использования. Если ставите DocGen на публичный домен, ограничьте доступ на уровне reverse-proxy (basic auth, allowlist) — встроенной авторизации в текущей версии нет.
- **Файлы генерируются в памяти и отдаются в ответе** — на диске сервера они не сохраняются; база содержит только справочники и шаблоны, а не введённые пользователями данные.
- **Android-приложение — тонкий клиент**: единственное разрешение `INTERNET`, минимум API 26, целевой SDK — актуальный; адрес сервера хранится локально в приложении. Отводите серверу HTTPS: трафик между клиентом и сервером содержит содержание документов.
- **Ссылки на госпорталы** ведут только на официальные домены (gosuslugi.ru, diia.gov.ua, egov.kz, my.gov.uz, portal.tunduk.kg, mygov.az и др.) и открываются во внешнем браузере.
- **Подпись APK**: ключ стабильный, SHA-256 сертификата зафиксирован в README и в пине workflow; APK из чужих источников (не Releases) устанавливать не следует.

## Что не считается уязвимостью

- Отсутствие встроенной аутентификации при публичном развёртывании без reverse-proxy — см. рекомендации выше.
- Предупреждения SmartScreen (Windows) и Gatekeeper (macOS) для неподписанных десктоп-сборок — следуйте инструкции установки в README.
- Отказ Android-оболочек устанавливать APK из «неизвестных источников» без явного разрешения пользователя — штатное поведение Android.
